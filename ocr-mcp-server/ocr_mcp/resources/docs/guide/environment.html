01 / Before you edit

A small file.
A few rules.

The file is a contract between you and the launchers. Three habits keep it safe.

01 / The template

Keep .env.example intact.

Copy the template to .env and edit only the copy. The versioned template stays the reference; your file holds local values and secrets. Never commit or publish .env.

02 / The format

One name, one value.

Each line is NAME=value. No spaces around the equals sign, no comments on a value line that change its meaning, and use a plain-text editor so the file keeps its encoding and its leading dot.

03 / The role

A file, not a document.

.env is read by the launcher and Compose; it is not documentation for others and not a place for prose. This guide explains every name so the file can stay terse.

02 / Day one

Change three secrets.
Leave the rest.

The template defaults carry the whole first run. Only the credentials need your decision.

Set OCR_SERVER_API_TOKENS to a strong random secret followed by a label such as :console — the console's API key field takes the secret alone. Set MCP_API_TOKENS to a different secret followed by :local-agent. Set UPSTREAM_CLIENT_TOKEN to a third plain secret, no label: the MCP server presents it to the API, which accepts it automatically.

Everything else stays at the shipped defaults for a first run: ports, budgets, GPU overrides and the storage profile. Reach for them when a real need appears — every name below is documented.

Your three assignments · placeholder values 
OCR_SERVER_API_TOKENS=<strong-random-secret>:console
MCP_API_TOKENS=<different-secret>:local-agent
UPSTREAM_CLIENT_TOKEN=<third-secret>

Illustrative placeholders — generate real secrets on your own machine and keep them out of chat.

03 / Precedence & file rules

Separate the template
from your values.

Defaults are a contract. Local credentials are not documentation.

01 / Template vs working copy

Keep .env.example intact

Use .env.example as the versioned reference and .env for local values. Compose reads the selected env file; it does not automatically read the example.

02 / Override order

Know which value wins

CLI selection overrides shell values, then the selected env file, then the Compose ${VAR:-fallback} — missing and empty values both use the fallback. Inside ocr-api an empty OCR_VL_LANES, OCR_PAGE_PARALLELISM or OCR_LAYOUT_THREADS falls through to the calibrated hardware profile, every other empty value to the built-in default; GPU overrides stay empty for automatic hardware selection.

03 / Container vs native

Check runtime scope

The native API reads its process environment, not a dotenv file. Native MCP started from a source checkout also reads the repository root .env (the shell still wins); an installed package reads only its process environment. Section 14 entries are commented native examples and are not forwarded by Compose.

Units & empty values

Most deadlines are seconds and byte budgets are bytes; OCR_HEALTH_START_PERIOD is a Compose duration. Each entry below records the template value exactly, even when empty.

04 / Optional S3 archive

Archive outputs.
Only when asked.

The storage profile is off by default. The API runs the same without it — enabling it adds SeaweedFS, a gateway and a one-shot initializer.

Run python scripts/configure_storage.py to activate it. The helper writes into .env — locally, never printed. It always switches on the three activation keys and fills the rest only where empty:

  • Activation. OCR_STORAGE_ENABLED=true, OCR_STORAGE_BROWSER_ENABLED=true, and storage added to COMPOSE_PROFILES.
  • Behaviour. OCR_S3_BUCKET=ocr-outputs, OCR_S3_RETENTION_DAYS=30, OCR_STORAGE_SAVE_PARSED=true, OCR_STORAGE_SAVE_INPUT=false.
  • Credentials. Separate least-privilege key pairs for admin, writer, reader and browser roles — OCR_S3_* and OCR_SEAWEED_* names in section 13 — generated only where empty.

On the next up, startup runs the synchronous bucket and identity initializer before the API. Disabling the profile later excludes it from future start plans; already running storage containers remain until stopped or down.

What the helper writes · shape only 
COMPOSE_PROFILES=…,storage
OCR_STORAGE_ENABLED=true
OCR_STORAGE_BROWSER_ENABLED=true
OCR_S3_BUCKET=ocr-outputs
OCR_S3_RETENTION_DAYS=30
OCR_S3_* / OCR_SEAWEED_* = generated locally

Existing credentials and behaviour values are preserved, the activation keys are always set; secrets are never displayed. Groups 12 and 13 below document every name.

05 / Access & credentials

Trace each credential
to its target.

The OCR stack uses distinct labelled credentials for the API and MCP, plus one service token between them.

You → OCR API (:8020)

API inbound

OCR_SERVER_API_TOKENS holds unique token:label pairs; clients send the token half alone. Empty disables API authentication. Health, enabled docs and frontend assets stay public.

Agent → MCP (:8021)

MCP inbound

MCP_API_TOKENS holds unique token:label pairs, separate from the API secret. Compose requires credentials even on host loopback.

MCP → OCR API

MCP outbound

UPSTREAM_CLIENT_TOKEN is one plain service token. The API accepts it automatically under the label @mcp, so it never goes in the API list. Required when API authentication is on.

Host → vLLM (:8081)

Model server

The published vLLM port has no configured bearer authentication. The OCR API token does not protect it. Keep loopback publications; CORS is not an access token.

Protect a full stack in four steps.

  1. Set the API credentials. OCR_SERVER_API_TOKENS gates the console and every API call, plus a separate UPSTREAM_CLIENT_TOKEN for the MCP server.
  2. Set a different MCP secret. MCP_API_TOKENS uses its own token:label list — reusing the API secret blurs two boundaries.
  3. Keep loopback publications. Every host port is 127.0.0.1 in Compose, including unauthenticated vLLM docs on OCR_VLLM_DOCS_PORT.
  4. Separate storage roles. When the archive is enabled, OCR_S3_* identities carry least-privilege roles — never share them with the API or MCP secrets.
Different doors. Different keys. 
Console / REST → :8020 → OCR_SERVER_API_TOKENS (token:label)
Agent        → :8021 → MCP_API_TOKENS (token:label)
MCP          → API   → UPSTREAM_CLIENT_TOKEN
Host browser → :8081 → no bearer — keep loopback
Archive      → :8333 → OCR_S3_* role keys

Each door checks only its own key. The API also accepts the MCP service token, logged as @mcp.

06 / Apply a change

Save. Verify.
Apply.

Edits take effect through the launcher, not by saving alone. Three steps keep the change deliberate.

Both shells stay listed; your choice is emphasized and never hidden. Print shows both.

  1. Save and verify.

    Save .env in your editor, then run verify. It checks the token/storage relationships and Compose security without touching Docker state — fix what it names before applying.

    Run from the repository root

    Windows · PowerShell 7 
    pwsh .\stack.ps1 verify
    Linux / macOS · Bash 
    bash stack.sh verify

  2. Preview the resolved file.

    config prints the resolved Compose configuration with credentials redacted — check the value you changed is the one Compose will see. Shell variables still win over the file.

    Run from the repository root

    Windows · PowerShell 7 
    pwsh .\stack.ps1 config
    Linux / macOS · Bash 
    bash stack.sh config

  3. Apply and check health.

    Use up when .env changed — restart reuses the existing container configuration and keeps the old value. Afterwards, check /health for status=healthy and vllm=reachable.

    Run from the repository root

    Windows · PowerShell 7 
    pwsh .\stack.ps1 up -Wait
Invoke-RestMethod http://127.0.0.1:8020/health
    Linux / macOS · Bash 
    bash stack.sh up --wait
curl --fail --show-error --silent http://127.0.0.1:8020/health

03 / API and MCP authentication3 settings
OCR_SERVER_API_TOKENSActive assignment
Template: (empty)

Inbound API and console token:label entries separated by commas; clients and the console's API key field use the token half alone. Tokens and labels must be unique; labels match [A-Za-z0-9._-]+. When set, everything except /, /health, /assets/* and the enabled OpenAPI routes requires the bearer token, including /stats and /metrics. Empty disables API authentication. Replaces the former OCR_SERVER_API_TOKEN, which is now refused. Never put a real token in this guide.

MCP_API_TOKENSActive assignment
Template: (empty)

Inbound MCP token:label entries separated by commas. Tokens and labels must be unique; use secrets distinct from the API tokens and the service token. Required by Compose MCP: empty fails verify and the container start — start with -NoMcp / --no-mcp or MCP_SERVER_ENABLED=false instead.

UPSTREAM_CLIENT_TOKENActive assignment
Template: (empty)

Plain MCP-to-API service token, no label. ocr-api accepts it automatically as @mcp, so it must not appear in OCR_SERVER_API_TOKENS. Required when API authentication is on and MCP is enabled; host-side live verifiers send it too. ocr-api ignores it while OCR_SERVER_API_TOKENS is empty.

OCR_TABLE_REREADActive assignment
Template: (empty)

Such a block comes back cut to a stub or with repeated rows; /parse and /parse/chunks then read it once more at two megapixels and keep the second reading only when it passes the same checks and says more than the first. The table_suspect warning names the block and the outcome either way. false only warns; empty keeps the built-in default (true).

08 / Common questions

Apply changes
deliberately.

Validate the configuration before rebuilding and recreating containers.

Can this page edit my local settings?

No. This is a static reference to the versioned template. It never reads your .env, accepts a credential or saves changes.

How do I apply a change?

Run from the repository root

Windows · PowerShell 7 
pwsh .\stack.ps1 verify
pwsh .\stack.ps1 up -Wait

Linux / macOS · Bash 
bash stack.sh verify
bash stack.sh up --wait

Restart alone retains container configuration. Check shell overrides if the applied value differs from your file.

How are storage secrets created?

Run from the repository root

Windows · PowerShell 7 
python scripts/configure_storage.py

Linux / macOS · Bash 
python3 scripts/configure_storage.py

The helper generates missing credentials locally, preserves existing values and enables the storage profile. It is an explicit operator action; this guide does not run it.

Why did changing a Section 14 variable do nothing in Docker?

Section 14 documents native-process variables (such as MCP_UPSTREAM_URL and OCR_VLLM_URL). Stock compose.yml pins internal container URLs and bind addresses directly so host port edits do not break container-to-container routing.
