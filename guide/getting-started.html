01 / Install and start

One settings file.
One start command.

Use the supplied defaults for your first run. The only file you create is .env; the launcher chooses the rest.

  1. Create the .env file.

    Open a terminal in the folder containing stack.ps1, stack.sh and .env.example. Copy .env.example to .env — the commands alongside do this only if .env does not already exist. If you already have one, keep it.

    Open .env in a plain-text editor. Keep the filename exactly .env, not .env.txt. This file holds your local configuration and secrets; never publish it.

    Run from the repository root

    Windows · PowerShell 7 
    if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}

    Linux / macOS · Bash 
    if [ ! -e .env ]; then cp .env.example .env; fi

  2. Set three distinct secrets.

    Edit .env locally. Set OCR_SERVER_API_TOKENS to a strong random secret followed by :console, MCP_API_TOKENS to a different secret followed by :local-agent, and UPSTREAM_CLIENT_TOKEN to a third secret with no label.

    The template leaves credentials empty: API authentication is then disabled and MCP HTTP startup is refused. For an intentional API-only setup, start with -NoMcp / --no-mcp instead.

    You → OCR API (:8020)

    OCR_SERVER_API_TOKENS

    A strong random secret followed by :console. It gates every route except /, /health and the console's static assets; the label only names it in the log.

    Agent → MCP (:8021)

    MCP_API_TOKENS

    A different secret followed by :local-agent. With this list empty, verify reports it and the MCP server refuses to start.

    MCP → OCR API

    UPSTREAM_CLIENT_TOKEN

    A third secret, no label. The MCP server presents it to the API, which accepts it automatically — keep it out of the API list.

    The token relationship matters

    MCP credentials open MCP only. The API accepts UPSTREAM_CLIENT_TOKEN automatically as @mcp; it must appear in neither OCR_SERVER_API_TOKENS nor MCP_API_TOKENS, and verify refuses a file that lists it. See the authentication map ↗.

  3. Verify the configuration.

    verify checks tokens, storage settings and Compose security without touching Docker state. Resolve anything it reports before starting — it is faster to fix .env now than to diagnose a half-started stack.

    It is a preflight, not a health check: it validates your file, not the services.

    Run from the repository root

    Windows · PowerShell 7 
    pwsh .\stack.ps1 verify

    Linux / macOS · Bash 
    bash stack.sh verify

  4. Build and start
    the stack.

    Run the command for your terminal. up re-runs verify, builds the images and starts the services in readiness order; the wait flag holds until MCP listener health too.

    First-run budget: the first start builds images, downloads the model and runs calibration — allow tens of minutes. Later starts reuse the cached work.

    Run from the repository root

    Windows · PowerShell 7 
    pwsh .\stack.ps1 up -Wait

    Linux / macOS · Bash 
    bash stack.sh up --wait

    Expected sequence
    Verify → build images → wait for vllm-paddleocr → optional storage init → API calibration → MCP listener health. If startup reports an error, use the startup checks below.

  5. Connect the app's MCP.

    The server in ocr-mcp-server/ gives your agent the extraction tools. Connect the client you actually use, such as Codex or Claude Code.

    Using only the browser console? Continue to the console — this step and the next are for agent access.

    One local MCP connection

    Transport: Streamable HTTP. Server URL, with the supplied settings:

    http://127.0.0.1:8021/mcp

    Authenticate with the header Authorization: Bearer <your MCP token> — a raw token from MCP_API_TOKENS, without its :local-agent suffix. Keep the real token in your client's secret mechanism, not in chat or shared configuration. A wrong token fails the session.

    Documents reach the server as base64 by default: MCP_INPUT_ROOTS ships empty and the container mounts no host folder, so file_path inputs stay off until you set the roots and mount that folder read-only into ocr-mcp. The skill sends base64 on its own.

    Register this name, transport, URL and bearer header in your client's MCP settings — see the official client documentation linked inside each answer. The server guide documents the transport; the client commands belong to the client.

    Connect Codex

    Codex keeps personal MCP connections in its own configuration. Follow its documented MCP setup to add a Streamable HTTP server named for this app at the URL above, supplying the bearer token through the client's supported secret mechanism. Official Codex MCP setup ↗

    Equivalent manual configuration in each shell's home folder — illustrative, prefer the documented client command:

    Check the registered servers

    Windows · PowerShell 
    Get-Content "$env:USERPROFILE\.codex\config.toml"
    Linux / macOS · Bash 
    cat "$HOME/.codex/config.toml"

    Connect Claude Code

    Add a user-scoped HTTP MCP server at the URL above through Claude Code's documented MCP setup, supplying the bearer token through its supported secret mechanism. Official Claude Code MCP setup ↗

    After registering, the entry lives in the client's own configuration:

    Check the registered servers

    Windows · PowerShell 
    Get-Content "$env:USERPROFILE\.claude.json"
    Linux / macOS · Bash 
    cat "$HOME/.claude.json"

    Next: reopen your agent session or reload its MCP connections, then check its connected-server list. In the Codex CLI and Claude Code, /mcp shows the connection. Then install the skills below.

  6. Install the supplied skills.

    ocr-skill/ contains two skills: smart-document-manager governs every OCR MCP call, a health check as much as an extraction, and carries the best practices the tools alone do not; smart-document-reader reads an existing /parse result or its stored archive — order, tables, captions and provenance.

    Copy each skill's SKILL.md and references/ — evals/ is test material the client does not need. The commands keep an existing destination: compare its contents with the supplied copy before replacing local changes. Skill installation reference ↗

    Choose your client and run the matching commands from the repository root. A copied folder alone does not load a skill — the client loads it from its skills directory.

    Install for Codex

    Destinations: ~/.agents/skills/smart-document-manager and ~/.agents/skills/smart-document-reader. Here ~ means your home folder.

    Run from the repository root

    Windows · PowerShell 
    foreach ($skill in 'smart-document-manager', 'smart-document-reader') {
    $target = "$env:USERPROFILE\.agents\skills\$skill"
    if (Test-Path -LiteralPath $target) {
        Write-Output "$skill already exists. Compare it with the supplied copy."
    } else {
        New-Item -ItemType Directory -Force $target | Out-Null
        Copy-Item -Path ".\ocr-skill\$skill\SKILL.md", ".\ocr-skill\$skill\references" -Destination $target -Recurse
    }
}
    Linux / macOS · Bash 
    for skill in smart-document-manager smart-document-reader; do
    target="$HOME/.agents/skills/$skill"
    if [ -e "$target" ] || [ -L "$target" ]; then
        printf '%s\n' "$skill already exists. Compare it with the supplied copy."
    else
        mkdir -p "$target"
        cp -R "ocr-skill/$skill/SKILL.md" "ocr-skill/$skill/references" "$target/"
    fi
done

    Reopen Codex if the skills have not appeared, then select them in the client. Official Codex skill setup ↗

    Verify from your agent

    After loading the skills, send this read-only request in the same client you connected:

    Use the smart-document-manager skill. Call ocr_check_health with params {"response_format":"json"}. Report the services it checks and their status. Do not change any data.

    You are ready when the agent has loaded the skill, can call the MCP tool and the response reports the services healthy. A saved configuration or copied folder alone does not confirm that. Then try the first extraction walkthrough.

04 / The structured result

Read the blocks
in reading order.

  1. Open the structured JSON: content arrives as labelled blocks, each with a block_id.
  2. Read the blocks in block_id order — that is the document's reading order. A null order comes from the label (captions, tables, headers…), not from a missing position.
  3. Link a caption to its figure or a footnote to its marker from block_id adjacency and labels — the JSON has no relations field; bbox and page keep where each block came from.

What to checkThe markdown and the block list tell the same story. Compare a few recognized lines with the original page — the fixture's form943.txt is the expected text.

An example of reading order / values abbreviated

title → field labels → table rows → footnote

The smart-document-reader skill documents how to read order, relations and provenance without re-running OCR.

06 / RAG tab

Refine a saved
JSON RAG.

  1. Open RAG. It lists the json_rag.json files saved in Storage archives, so it needs the optional storage profile and a parse with json_rag checked. Without storage, skip this step.
  2. Select an original json_rag.json, keep the min token / max token targets and choose Run preflight. The targets are best-effort, not a strict limit.
  3. Review the groups, cut or merge where needed, then choose Execute and save JSON RAG: a refined file is saved beside the original.

What to checkEach group is classified within, below or above range, and the original json_rag.json stays unchanged. For strict token-bounded chunks, call POST /chunk with the full /parse JSON and an explicit options.max_tokens.

01 / Formats

JSON vs markdown.

Markdown is the document reassembled for people. The JSON carries the same content as labelled blocks with positions, reading order and provenance — the shape agents and pipelines consume.

02 / Honesty

Read warnings and truncation.

Page warnings report what recognition could not confirm. Truncation marks where a budget — pages, size or output — cut the result. A truncated page is incomplete, not failed. When the time budget runs out, the finished pages still return and the rest are marked unprocessed.

03 / Provenance

Every block knows its place.

block_id order is the reading order; a null order is set by the label, not a missing position. Each block keeps the page and region it came from, so a quoted line traces back to the source.

06 / Troubleshooting

Follow the failure
to its service.

Start with the reported error and the last service whose readiness did not complete.

Startup timed out. What should I inspect?

Run from the repository root

Windows · PowerShell 7 
pwsh .\stack.ps1 status
pwsh .\stack.ps1 logs -Service ocr-api,vllm-paddleocr -Tail 100

Linux / macOS · Bash 
bash stack.sh status
bash stack.sh logs --service ocr-api,vllm-paddleocr --tail 100

A timeout preserves containers and volumes for diagnosis. Check GPU/runtime availability, downloads and calibration logs before changing the wait budget.

MCP refuses startup, or calls return 401.

Check MCP_API_TOKENS=token:label, unique labels/tokens and separation from the API secrets. With API authentication on, UPSTREAM_CLIENT_TOKEN must be set (plain token, no label) and must not appear in OCR_SERVER_API_TOKENS.

The browser cannot connect.

Run urls to see configured addresses and status for container state. All host publications are loopback. A configured URL is not a live health check.

Health returns HTTP 200, but status is degraded.

The API container is listening, but vllm-paddleocr is still loading weights or unreachable. Inspect vllm-paddleocr logs and confirm GPU memory availability before submitting documents.

If instead /health says status=healthy with mode=archive_only and vllm=disabled, nothing is wrong: the stack was started with -ArchiveOnly / --archive-only on purpose. Stored archives are readable; OCR returns with a plain up (after editing or overriding OCR_ARCHIVE_ONLY if .env fixes it to true).

In archive-only mode a degraded status means the archive bucket probe has not succeeded yet, or has failed: check the storage services; vLLM is not involved.

Can I read my archives without the GPU?

Yes. pwsh .\stack.ps1 up -ArchiveOnly or bash stack.sh up --archive-only starts the API, MCP and, when COMPOSE_PROFILES=storage, the storage profile, without vllm-paddleocr and without reserving a GPU, so no VRAM is allocated. The console opens on its Storage tab with Parse and OCR hidden, and together with the /storage/* routes and the MCP storage tools it works on everything archived earlier; the OCR routes answer 503 ocr_disabled_archive_only. It needs storage and its browser enabled — see the CLI guide.

Can I parse a Word, Excel or PowerPoint file?

Yes. /parse and the console's document field accept Office formats — .docx, .pptx, .xlsx, the legacy .doc/.ppt/.xls and OpenDocument types. The API renders them to PDF with LibreOffice before layout recognition, so allow extra time for the conversion.

The focused /ocr route is different: it recognizes a single image element and refuses PDF and Office bytes.

Startup complains about GPU memory, or recognition stalls.

vllm-paddleocr needs free GPU memory for the model and its runtime budget, and layout analysis in ocr-api (container smart-document-manager) shares the same card (OCR_LAYOUT_GPU_MEMORY_MB). Other GPU processes compete for the same memory — check what else is using the device before starting. On a machine with several GPUs, move the stack to a free card with -GpuDevice 1 / --gpu-device 1 or OCR_GPU_DEVICE. On an 8 GB card, restart both services together.

Keep the GPU override settings empty until you have a measured reason to change them; the launcher tiers and budgets from the hardware it finds. If memory is the proven limit, reduce concurrent load rather than forcing a configuration.

My agent connected to MCP but sees no tools.

Reload the MCP connection or reopen the agent session — clients typically discover tools at connect time. Then check the connected-server list; in the Codex CLI and Claude Code, /mcp shows the connection.

If the server is listed but calls fail, re-check the bearer: it must be a raw token from MCP_API_TOKENS without its :label suffix, sent as Authorization: Bearer. A copied skill folder does not create the MCP connection — both steps are needed.

Chunking refused my request or split badly.

Chunk creation is opt-in and requires an explicit options.max_tokens budget — a request without one is refused. In strict mode, the default, a budget smaller than a single protected unit also cannot be satisfied.

Send the complete /parse JSON to POST /chunk as parsed_document rather than re-parsing; the json_rag export is not chunker input. If chunks split poorly, raise the budget instead of forcing smaller units; provenance on each chunk still traces back to its source blocks.
