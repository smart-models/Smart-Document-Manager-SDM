01 / The big picture

Layout. Recognition.
Reading order.

Three ideas carry the whole pipeline: a page is a map of labelled regions, a model fills each region in, and block_id — not position — decides how to read it.

FIND THE REGIONS▦

Layout labels every region.

PP-DocLayoutV3 scans each page image and returns labelled regions — text, titles, tables, figures, formulas, seals — each with a bounding box in raster pixels.

25 block types from body text to seals and page numbers.
FILL THE REGIONS✎

Recognition reads each block.

The API crops every labelled region and PaddleOCR-VL on vllm-paddleocr turns it into text, an HTML table, a LaTeX formula or an image reference.

Per-block content lands back on the block, never loose text.
READ IN ORDER≣

block_id is the order.

Read blocks in block_id order for every page. A null order is a label choice — captions, headers and tables still have a fixed place in block_id.

Never rebuild order from bounding-box coordinates.
Then the evidence

The JSON keeps warnings and per-page errors; captions and footnotes link to their objects by block_id adjacency and label. Markdown is a rendering of the same blocks — not a second opinion.

05 / Rebuild the reading

Order. Relations.
Provenance.

block_id gives the reading order for every block on the page. Captions sit next to their tables and figures in block_id, and footnote markers point to notes on the same page — the JSON has no relations field, so links come from these reading rules. Every block keeps its bbox — p{page}:b{block_id} addresses any fact back to its region.

ocr-api · assembly and normalization
A null order is a label choice, not a missing position — block_id is the order.

b4footnote — marker † resolvedno order

Prefer to read? The page in six sentences
  1. Rasterize. Every input becomes page images inside a per-page pixel budget and a page cap, in blocks of up to 24 pages; Office files are converted to PDF first.
  2. Detect. PP-DocLayoutV3 finds the regions and gives each a bounding box.
  3. Label. Each region receives one of 25 tags; the label decides order eligibility and Markdown membership.
  4. Recognize. PaddleOCR-VL reads each region and its content lands back on the block.
  5. Order. block_id numbers every block in reading order; captions and footnotes link to their objects by adjacency and label.
  6. Render. JSON keeps the full structure with warnings and page errors; Markdown renders the same blocks for reading.

05 / Division of labour

Four workers.
One page.

Each pass in the journey belongs to a different part of the stack. Knowing who does what tells you where a surprising output can come from.

ocr-api · FastAPI

The API validates and orchestrates

Admission budgets, Office conversion, rasterization, dispatch and final assembly all live in the API. Per-page failures become structured page errors instead of a failed request.

Owner of warnings — check warnings[] and pages[i].error first.
PP-DocLayoutV3 · pipeline backend

Layout runs on the API side

Region detection and labelling happen inside the OCR API's pipeline, not on the model server. The 25 tags and every bounding box come from this stage.

A map, not a reading — regions exist before any content.
vllm-paddleocr · NVIDIA GPU

PaddleOCR-VL recognizes

The vision-language model reads each cropped region and returns text, HTML tables, LaTeX or image references. Recognition needs the GPU; a page that fails VLM recognition surfaces as a page error.

Per-block content under lane, slot and memory budgets.
PaddleOCR tokenizer · CPU

The tokenizer counts

The local PaddleOCR-VL tokenizer already counts each block's content_tokens during /parse and sums them in the top-level usage. When the same JSON is later chunked for RAG, the chunker reuses that tokenizer on CPU — no second GPU inference. Same input and options give byte-identical chunks.

Deterministic — see the RAG chunking guide ↗.
06 / Practical trade-offs

Three dials
shape the result.

Parse options trade fidelity against time and payload size. They are per-request choices — the template defaults suit most first reads. Two more shape the payload: output (markdown, json or both, default both) chooses which of markdown and blocks each page carries, and json_rag=true adds a separate top-level json_rag export, null unless requested or when json_rag_failed is reported.

Dial / Coverage vs time

max_pages and dpi

max_pages caps how many pages are parsed — a truncated result sets pages_truncated, so say the document is partial; a value above OCR_MAX_PAGES is rejected with 422. dpi (50–400) sets raster density for PDF and Office pages: higher reads small print better and costs more time per page, inside the 25M per-page pixel cap. On image input it is ignored with a dpi_ignored warning.

Dial / Table shape

table_format

Tables can render as html (the API default, with rowspan/colspan spans) or markdown; the console preselects markdown · pipes. HTML keeps merged cells exact; markdown tables are easier to quote but lose span structure.

Dial / Visual evidence

include_images

Off by default in the API; the console's include figures box starts checked. When enabled, each page carries base64 PNG crops in images with matching image_names; a crop over OCR_MAX_EMBEDDED_IMAGE_BYTES is skipped with an images_truncated warning. When off, visual blocks still appear as imgs/img_in_*_box_… references in Markdown and as typed blocks in JSON.

07 / Glossary & further reading

A little less jargon.
One level deeper.

Terms this page uses, and the owning documents that define the exact behavior.

What is block_id?

The per-page index of a block and its reading order. Read blocks[] in block_id order; never re-sort by bounding box. p{page}:b{block_id} is the provenance address of any fact.

Why is order null?

order is null by label — table, figure_title, image, chart, vision_footnote, footnote, header, footer, number, aside_text, header_image and footer_image never get one. Null means "this label is not numbered", not "unplaced": the block still has its block_id position.

What is bbox?

A block's bounding box in raster pixels, origin top-left: [x0, y0, x1, y1]. Use it to point back at the page or to crop a region for a focused /ocr task — not to reconstruct reading order.

What is a relation?

A link between blocks — a caption to its table or figure, a footnote marker to its note. The /parse JSON has no relations field: resolve links from block_id adjacency and labels, as the smart-document-reader skill describes. The RAG chunker records them as relations on chunks, with status unresolved when evidence is missing — never invented.

What does markdown contain?

A rendering of the same blocks: headings, paragraphs, tables and image references. Marginal furniture — headers, footers, page numbers, side text — never reaches it, and neither do footnotes or equation numbers. When output="markdown" was requested, blocks can be null and markdown is the only source.

What is a warning?

A structured note about degraded evidence — truncation, a partial page, pages left unprocessed when the time budget ran out, a skipped element. Top-level warnings[] plus per-page error fields tell you how complete a result is before you trust it. Each warning carries code, severity (warning or info), message, target and details. Codes: pages_truncated, pages_unprocessed, page_failed, office_converted, tables_spans_expanded, images_truncated, json_rag_failed, dpi_ignored.

What is an element task?

/ocr takes one image and one task — ocr, table, formula, chart, spotting or seal — and returns result, task, boxes, model_name, processing_time_ms and warnings. Spotting boxes are axis-aligned envelopes in normalized 0–1000 units, not pixels. When generation stops at the token limit the partial result still arrives with HTTP 200 and a generation_truncated warning; the server never retries it.

What is group_id?

A grouping hint between neighbouring blocks — an empty text block can share a group_id with the block holding its text. It is not a block_id and does not change the reading order.

What is page furniture?

The marginal labels: header, footer, number, aside_text, header_image, footer_image. They describe the page, not its body — keep them as metadata, out of quotations.

08 / Questions

Read the JSON
like evidence.

Match each surprise in a result to the field that explains it.

Why is markdown null or partial?

Check the request's output and top-level warnings. When blocks is null the parse ran with output="markdown": the Markdown is the only source — cite by page, say that headers, footers, page labels and side text are absent, and re-parse with output json or both if you need the structure.

Why does a block have empty content?

An empty text block sharing a group_id with a non-empty block keeps its text there — read the group, not the single block. Empty visual blocks (image, chart, seal) are normal: mention presence and captions, never describe or quote pixel content.

One page failed — is the rest usable?

Yes, with a caveat. A per-page error means that page is unreliable or missing while the others returned normally; pages_truncated means only the first pages were parsed at all; pages_unprocessed lists pages never reached before the time budget ran out, while the finished pages still return. Name the gap and never call a partial result the whole document.

A caption points at nothing — what happened?

A figure_title without an adjacent object is only a possible continuation — its figure or table may live on the next page. Verify matching evidence there; otherwise report the association as unresolved rather than guessed.

Should I rebuild order from bounding boxes?

No. block_id already is the reading order — including tables, captions and vertical text, which ran right to left on the pages observed. Coordinates are provenance for pointing back at the page, not a sort key.

Why does one page show two doc_titles?

A page can genuinely hold two articles, or the second doc_title is a subtitle or subject line. Confirm from the content around it before treating it as the title.
